# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

**Hades Gate** is a meta-framework — not a project itself, but a structured loop for turning ideas into code across any project. It separates the **Architect** role (Gemini analyzes and proposes) from the **Builder** role (Claude implements). This repo contains only the framework tooling; actual projects symlink to `.hades/` via the Ghostwire protocol.

## Commands

All interaction happens via the `hades` CLI (aliased to the `hades` shell script in this repo).

```bash
hades seed              # Cultivate the Arche — scan the active project
hades genesis "Intent"  # Carve a seed into .hades/styx.md
hades ignite            # Strike the flint — send Arche + Styx to Gemini
```

Implementation typically happens in a live Claude session ("Implement Path B").

## Architecture

### The `.hades/` Folder

| File | Role | Git-tracked? |
|------|------|-------------|
| `manifesto.md` | Global coding standards injected into every Gemini prompt | Yes |
| `papyrus.md` | Template that defines the 3-path proposal structure | Yes |
| `styx.md` | User's seeds (raw intent/tasks) — input to `ignite` | **No** |
| `arche.md` | Project DNA snapshot generated by `seed` — input to `ignite` | **No** |
| `prions.md` | Gemini's 3-path proposals — output of `ignite` | **No** |
| `erebus.env` | `GEMINI_API_KEY=...` — sourced by the shell function | **No** |

### The Ghostwire Protocol

Projects that use Hades Gate symlink their `.hades/` to this repo's `.hades/`:
```bash
ln -s ~/Repositories/hades-gate/.hades ~/Repositories/my-project/.hades
```

This means `styx.md`, `arche.md`, and `prions.md` are **shared state** — only one active project at a time. The manifesto and papyrus are the stable, tracked parts; the generated/personal files are gitignored.

### `spark.py` — How It Works

**`seed` mode** (`cultivate_arche()`):
- Walks the active project's directory (filtered: no `.git`, `node_modules`, `_site`, etc.)
- Reads the project's `CLAUDE.md` verbatim as "Project Identity"
- Parses `.js` files into skeleton (function signatures only, no bodies)
- Writes everything to `.hades/arche.md`

**`ignite` mode** (default):
- Concatenates: `manifesto.md` + `arche.md` + `papyrus.md` + `styx.md`
- Sends as a single prompt to `gemini -p ...` via subprocess
- Writes stdout to `prions.md` and prints it to terminal

### The Proposal Format (Papyrus)

Every `ignite` run produces exactly 3 paths in `prions.md`:
- **Option A — The Fast Path:** minimal friction, immediate result, explicit trade-off
- **Option B — The Deep Path:** clean architecture, higher effort, the "dream" version
- **Option C — The Experimental Path:** outside-the-box or novel approach

The Evaluation Matrix at the bottom recommends which to crystallize.

## Workflow

1. `cd` into the active project (the one with the `.hades` symlink)
2. `hades seed` — update the Arche with current code state
3. `hades genesis "What you want to achieve"` — log intent to Styx
4. `hades ignite` — Gemini generates 3 proposals into `prions.md`
5. Review `prions.md`, pick a path, tell Claude in your **active session** to implement it
   - Claude reads `CLAUDE.md` (project rules) + `.hades/prions.md` (the chosen proposal)
   - No separate `execute` step — implementation happens in the ongoing conversation

## Adding a New Project

1. Symlink `.hades` as above
2. Add to the project's `CLAUDE.md`:
   ```markdown
   ## Hades Gate Integration
   - Before starting any task, check `.hades/prions.md` for the latest proposals.
   - Playtest data (if available) lives in `temp/playtest_logs`.
   ```
3. Run `hades seed` from the project root to populate `arche.md`
