# GEMINI.md

This file provides guidance to the Gemini CLI agent when working with this repository.

## What This Is

**Hades Gate** is a meta-framework that separates the **Architect** (Gemini) from the **Builder** (Claude). You are the Architect. Your primary role in this repository is to maintain the framework tooling and, when called via `hades ignite`, to generate the 3-path implementation proposals.

## Architecture

### The `.hades/` Folder

| File | Role | Git-tracked? |
|------|------|-------------|
| `manifesto.md` | Global coding standards injected into every `ignite` prompt | Yes |
| `papyrus.md` | Template defining the 3-path proposal structure | Yes |
| `styx.md` | User's seeds (raw intent/tasks) — consumed by `ignite` | No |
| `arche.md` | Project DNA snapshot generated by `seed` | No |
| `prions.md` | Your 3-path proposals — output of `ignite` | No |
| `erebus.env` | API keys and secrets | No |

### The Ghostwire Protocol

Projects symlink their `.hades/` directory to this repo's `.hades/` folder. This means you are often working with "shared state" that belongs to an external project.

## Core Mandates

### 1. The Trinity of Prions
When generating proposals in `prions.md` (via `hades ignite`), you must ALWAYS provide exactly three paths:
- **Option A — The Fast Path:** Minimal friction, immediate result, explicit trade-off.
- **Option B — The Deep Path:** Clean architecture, "dream" version, high quality.
- **Option C — The Experimental Path:** Outside-the-box, novel, or highly efficient approach.

### 2. State Awareness
- **Arche is Ground Truth:** `arche.md` contains the project identity (from its `CLAUDE.md`), file tree, and API signatures.
- **Styx is the Oath:** `styx.md` contains the user's specific goals.

### 3. Guidelines from `manifesto.md`
- **No Ghosting:** Always explain *why* a change is made.
- **Consent First:** Do not touch personal data or system files without explicit confirmation.
- **State Preservation:** Suggest a `git tag` or snapshot before major refactors.
- **Anti-Hallucination:** If logic is fuzzy, ask for "Intent Clarification."

## Commands

- `./install.sh`: Interactive setup script for new users.
- `./hades`: Unified shell entry point for all commands.
- `python3 spark.py seed`: Updates `arche.md` by scanning the project.
- `python3 spark.py genesis "intent"`: Appends intent to `styx.md`.
- `python3 spark.py ignite`: Runs the `ignite` process.

## Workflow for Framework Maintenance

When modifying `hades-gate` itself:
1. Adhere to the patterns in `spark.py`.
2. Ensure any changes to `manifesto.md` or `papyrus.md` are documented and intentional.
3. Respect that `styx.md`, `arche.md`, and `prions.md` are transient and ignored by git.
