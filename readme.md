## Hades Gate: The Primordial AI Forge

**Objective:** Materialize ideas into reality (Code) through a structured, multi-model feedback loop.

Hades Gate is a framework designed to bridge the gap between high-level architectural intent and low-level implementation. It separates the **Architect** (Gemini) from the **Builder** (Claude), ensuring that every line of code is driven by a deliberate "Seed" of intent.

---

### 🏛️ The Architecture of the Underworld

The framework is built on four distinct pillars:

* **The Styx (`styx.md`):** The river of memory where your "Seeds" (tasks/ideas) are carved.
* **The Arche (`arche.md`):** The "First Principle"—a primordial map of your project's current DNA, structure, and core logic.
* **The Spark (`spark.py`):** The catalyst that sends your Arche and Seeds to the void (Gemini) for analysis.
* **The Prions (`prions.md`):** Three infectious, high-fidelity proposals generated by Gemini, ready to mutate your codebase.

### ⚙️ Setup & Installation

#### 0. Dependencies
Install required dependencies via brew or other means to make them accessible within terminal:
- Claude Code
- Gemini CLI
- tree

#### 1. The Repository Structure
Ensure your directories are structured as follows:
```text
~/Repositories/
├── hades-gate/          # The Framework
│   ├── .hades/
│   │   ├── manifesto.md # Global coding standards
│   │   ├── papyrus.md   # Structure of a Prion
│   │   └── erebus.env   # API Keys (Git-ignored)
│   └── spark.py         # The Python catalyst
└── your-project/        # Your Active Project
    └── .hades/          # Symlinked "Ghostwire"
```

#### 2. The Ghostwire (Symlink)
To allow your project to communicate with the Gate, create a symbolic link between your project and the framework:
```bash
cd ~/Repositories/your-project
ln -s ~/Repositories/hades-gate/.hades .hades
```

#### 3. Authentication (Erebus)
Create `.hades/erebus.env` inside the `hades-gate` folder. **Do not commit this file.**
```bash
export GEMINI_API_KEY="your_google_ai_studio_key"
```

#### 4. The Terminal Alias
Add the `hades()` function to your `~/.zshrc` or `~/.bashrc` to control the Gate from anywhere.

---

### 🕹️ Command Usage

| Command | Action |
| :--- | :--- |
| `hades seed` | **Cultivate the Arche.** Scans your project files and updates the DNA map so the AI understands your current state. |
| `hades genesis "Intent"` | **Carve a Seed.** Writes your new task or feature idea into the Styx. |
| `hades ignite` | **Strike the Flint.** Sends your Arche and Seeds to Gemini. Three distinct implementation paths (Prions) will materialize in your terminal. |
| `hades execute B` | **Summon the Muscle.** Calls Claude Code to implement "Option B" from the Prions according to your Manifesto rules. |

---

### 🔄 The Workflow Loop

1.  **Map the Universe:** Run `hades seed` after structural changes so the AI knows your code.
2.  **Speak Intent:** Use `hades genesis` to define what you want to achieve.
3.  **Consult the Fates:** Run `hades ignite` to see three ways to solve the task.
4.  **Materialize:** Run `hades execute [A/B/C]` to have Claude implement the chosen path.
5.  **Observe:** Use the **Pulse** (Playwright/Browser) to verify the new reality and feed any "friction" back into the Styx for the next loop.

---

### 🛡️ Safety & Privacy
* **Ghostwire Protocol:** Your `.hades` folder is symlinked, meaning your private seeds and environment variables stay within the `hades-gate` repo.
* **Git Integrity:** Ensure `.hades/erebus.env`, `.hades/styx.md`, and `.hades/arche.md` are added to your `.gitignore` to prevent leaking your "First Principles" online.
